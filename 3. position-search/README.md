# Поиск позиции (Бинарный поиск)

## Условие задачи

Дан отсортированный по возрастанию массив целых чисел и заданное число. Если заданное число уже находится в массиве, верните его индекс. Если числа в массиве нет, верните индекс, где оно должно находиться, чтобы сохранить порядок сортировки.

## Формат входных данных

- В первой строке задаётся число `N` — количество элементов в массиве.
- Во второй строке вводится массив из `N` целых чисел, разделённых пробелами.
- В третьей строке задаётся число `target`, для которого нужно найти индекс.

## Формат выходных данных

Программа должна вывести одно число — индекс числа `target`, если оно уже есть в массиве, или индекс, где оно должно находиться для сохранения порядка сортировки.

## Пример

**Входные данные:**
```text
5
5 7 9 11 13
6
```

**Выходные данные:**
```text
1
```

*Пояснение: если бы в массиве было число 6, то оно находилось бы под индексом 1, то есть правее 5 и левее 7.*

## Решение

Решение написано на языке **Go (Golang)** и реализует классический алгоритм **Бинарного поиска (Binary Search)**.

### 1. Быстрый ввод-вывод (Fast I/O)

Как и в предыдущих задачах, используется обертка `IO` на базе `bufio.Scanner` и `bufio.Writer`. Это необходимо для быстрого чтения массива и мгновенного вывода результата.

### 2. Логика решения (PositionSearch)

Функция `PositionSearch` использует итеративный подход с двумя указателями:
1. **Инициализация:** Указатель `left` ставится на начало массива (`0`), а `right` — на конец (`n - 1`).
2. **Цикл поиска:** Пока `left <= right`, алгоритм находит середину (`middle`). 
   * Если `nums[middle] == target`, элемент найден, возвращается его индекс.
   * Если `nums[middle] < target`, значит искомое число находится правее, сдвигаем `left = middle + 1`.
   * Если `nums[middle] > target`, число левее, сдвигаем `right = middle - 1`.
3. **Возврат точки вставки:** Если элемент так и не был найден, цикл завершается. В этот момент указатель `left` будет указывать ровно на тот индекс, куда нужно вставить `target`, чтобы массив остался отсортированным (этот подход также известен как `lower_bound` в C++).

### 3. Сложность алгоритма

* **Время (Time Complexity): O(log N)**. На каждой итерации цикла область поиска (расстояние между `left` и `right`) сокращается ровно в два раза. 
* **Память (Space Complexity): O(1)**. Используется только несколько переменных для хранения указателей, дополнительная память под массивы или структуры не выделяется.
