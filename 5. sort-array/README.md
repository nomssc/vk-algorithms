# Сортировка массива

## Условие задачи

Дан неотсортированный массив целых чисел. Ваша задача — отсортировать массив по возрастанию, используя любой алгоритм сортировки.

## Формат входных данных

- В первой строке задаётся число `N` — количество элементов в массиве.
- Во второй строке вводится массив из `N` целых чисел, разделённых пробелами.

## Формат выходных данных

Программа должна вывести массив, отсортированный по возрастанию. Элементы массива разделяются пробелами.

## Пример

**Входные данные:**
```text
4
3 2 1 8
```

**Выходные данные:**
```text
1 2 3 8
```

## Решение

Решение написано на языке **Go (Golang)** и реализует алгоритм быстрой сортировки (**QuickSort**).

### 1. Быстрый ввод-вывод (Fast I/O)

Используется обертка `IO` над `bufio.Scanner` и `bufio.Writer`. Это позволяет очень быстро считывать и выводить большие объемы данных, что критически важно для задач на сортировку.

### 2. Логика решения (QuickSort)

Быстрая сортировка — это алгоритм, основанный на стратегии «разделяй и властвуй». В вашей реализации используется **схема разбиения Ломуто (Lomuto partition scheme)**:
1. **Выбор опорного элемента (pivot):** В качестве опорного элемента всегда выбирается последний элемент текущего подмассива (`nums[high]`).
2. **Разбиение (Partitioning):** Массив переупорядочивается так, чтобы все элементы, меньшие опорного, оказались слева от него, а большие или равные — справа. Для этого используются два указателя `i` и `j`.
3. **Рекурсия:** После того как опорный элемент встал на свою окончательную позицию (индекс `i`), функция рекурсивно вызывается для левой (`low` до `i-1`) и правой (`i+1` до `high`) частей массива.
4. **База рекурсии:** Если размер подмассива равен 0 или 1 (`low >= high`), сортировка завершается.

### 3. Сложность алгоритма

* **Время (Time Complexity):** 
  * В среднем и лучшем случае: **O(N log N)**.
  * В худшем случае: **O(N²)**. Это может произойти, если на вход подать уже отсортированный (или отсортированный в обратном порядке) массив, так как в вашей реализации опорным элементом всегда выбирается последний, что приводит к сильно несбалансированному разбиению.
* **Память (Space Complexity): O(log N)**. Хотя сам массив сортируется «на месте» (in-place, O(1) дополнительной памяти под данные), алгоритм использует стек вызовов рекурсии. В среднем глубина рекурсии составляет O(log N), но в худшем случае может достигать O(N).
